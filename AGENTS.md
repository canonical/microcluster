# AGENTS.md — MicroCluster Agent Instructions

MicroCluster is a Go library for building clustered microservices backed by dqlite.
Module: `github.com/canonical/microcluster/v4`.

## Prerequisites

- Go 1.25.7 or higher.
- On Debian/Ubuntu, install required build dependencies first:

  ```bash
  sudo apt-get update
  sudo apt-get install --no-install-recommends -y \
    shellcheck pkg-config autoconf automake libtool make \
    libuv1-dev libsqlite3-dev liblz4-dev
  ```

- CGO native dependency: dqlite. Fetch and build it once with:

  ```bash
  make deps
  ```

- Export dqlite CGO paths before building or running tests:

  ```bash
  export CGO_CFLAGS="-I$(go env GOPATH)/deps/dqlite/include/"
  export CGO_LDFLAGS="-L$(go env GOPATH)/deps/dqlite/.libs/"
  export CGO_LDFLAGS_ALLOW="(-Wl,-wrap,pthread_create)|(-Wl,-z,now)"
  export LD_LIBRARY_PATH="$(go env GOPATH)/deps/dqlite/.libs/${LD_LIBRARY_PATH:+:$LD_LIBRARY_PATH}"
  ```

- `golangci-lint` — installed automatically by `make check-static` if not present, or install manually:

  ```bash
  curl -sSfL https://golangci-lint.run/install.sh | sh -s -- -b $(go env GOPATH)/bin
  ```

```
  cluster/           Cluster member and token-record DB models

  daemon/            Daemon lifecycle and HTTP server wiring

  utils/             Validation utilities

  api/               Extended API handlers and types
  client/            Go client wrapper for the example API

test/
  lint/              Shell lint scripts run by make check-static

```

For deeper behavior and design context before editing clustering or schema code,
read `doc/clustering.md`, `doc/database.md`, and `doc/upgrades.md`.

### Generated and mapper files

The `*.mapper.go` files were originally generated by `lxd-generate` but the
`//go:generate` directives were intentionally removed.
These files are now **manually maintained** alongside the struct definitions
they map. Edit them by hand when adding or changing DB methods; do not attempt
to regenerate them via `lxd-generate`.

| File | How to update |
|------|---------------|
| `internal/cluster/cluster_members.mapper.go` | Edit manually alongside `cluster_members.go` |
| `internal/cluster/token_records.mapper.go` | Edit manually alongside `token_records.go` |
| `example/database/extended.mapper.go` | Edit manually alongside `extended_table.go` |
| `go.mod`, `go.sum` | `make update-gomod` |

## Build

There is no top-level build target; the library itself does not produce a
binary. To verify the library compiles:

```bash
go build ./...
```

To build the example binaries:

```bash
cd example
make build
```

## Validate before committing

Run these in order. Each must pass before moving on.

```bash
# 1. Static analysis (golangci-lint + shell lint scripts)
make check-static

# 1b. Example static analysis (required by CI)
make -C example check-static

# 2. Unit tests
make check-unit

# 2b. Example unit tests (required by CI)
make -C example check-unit

# 3. Example system tests (required by CI)
make -C example check-system
# For verbose system-test logs, use: DEBUG=1 make -C example check-system

# 4. If go.mod/go.sum or dependencies changed, verify minimum-Go compatibility
GOMIN="$(sed -n 's/^GOMIN=\([0-9.]\+\)$/\1/p' Makefile)"
go mod tidy -go="${GOMIN}"
# Expect no diff after this unless you intentionally changed dependencies.
```

## Running tests

Unit tests (no root, no daemon needed):

```bash
make check-unit
# or equivalently
go test ./...
```

Integration / system tests live in `example/test/main.sh` and require a
running environment. From the `example/` directory:

```bash
cd example && make check-system
```

Note: `make check-system` at the repository root is a no-op and always exits 0.

## Key conventions

Use `v4` as the default pull request target branch.
Use `v3` only when maintainers explicitly request `v3` for the change.
If branch targeting is unclear, ask maintainers before opening the pull
request.

### Commit format

All commits must be signed off (`git commit -s`). The sign-off is performed
by the human committer, not by an agent — see the DCO note below.

Format: `<scope>: <Short description>` — the description is capitalized and
in the imperative mood. The scope mirrors the changed path or package (kept as
it appears on disk, e.g. `Makefile`).

| Area | Example commit message |
|------|------------------------|
| `microcluster/` | `microcluster: Fix context shadowing in Start` |
| `internal/<pkg>` | `internal/daemon: Handle shutdown race` |
| `api` or `types` | `api: Add new member state type` |
| `example/` | `example: Extend microctl token command` |
| `test/` | `test: Add lint check for oneline assign` |
| `Makefile` | `Makefile: Add check-system target` |
| `doc/` | `doc: Document schema upgrade flow` |

`Signed-off-by` is a Developer Certificate of Origin (DCO) certification — a
legal assertion that you wrote or have the right to submit the code. Only a
human submitter can make this certification. AI agents must not add a
`Signed-off-by` line.

Agent handoff: AI agents may prepare commit messages, but a human committer
must run `git commit -s` and add the final trailers.

### Error messages

- Prefer `"Failed to <verb>"` (e.g. `"Failed to connect to peer"`) over the
  gerund `"Failed <verb>ing"`, matching the prevailing style across the
  codebase.
- Use `"cannot"` not `"unable to"`; no contractions (`"does not"` not `"doesn't"`).
- These rules apply to Go string literals only, not to code comments.

### Go style

- No inline variable declarations inside `if` conditions — assign on a
  separate line before the `if`.
- Prefer early returns to reduce nesting.
- Use the existing local test style: table-driven tests where applicable, and
  `stretchr/testify/suite` where package tests already use suites.
- Follow `.golangci.yml` rules; do not suppress linter warnings without a
  comment explaining why.
